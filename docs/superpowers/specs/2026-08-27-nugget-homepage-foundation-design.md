# 너겟 홈페이지 개편 — Phase 1: 기반 구축 설계

## 배경과 범위

`nugget.im`은 현재 아임웹(imweb, 노코드 빌더)에서 운영 중이며, `nugget-letter/page` 저장소는 그 화면을 정적 HTML로 복제해 둔 상태다. 이번 개편의 근본 동기는 **관리/유지보수 문제** — 아임웹은 블로그·채용공고 같은 콘텐츠를 실제 데이터 소스와 연동할 수 없어, 이후 명시적으로 **비주얼 디자인도 함께 새로 하는 전면 개편**으로 범위가 확장되었다.

전체 프로젝트는 4단계로 분해했고, 이 문서는 **1단계(기반 구축)**만 다룬다.

| 단계 | 내용 | 상태 |
|---|---|---|
| **1. 기반 구축** | imweb → Next.js/Vercel 이전, 새 비주얼 디자인 전체 섹션 적용, B2B 콘텐츠 신규 반영, 문의폼 실서비스 연결 | **이 문서의 범위** |
| 2. 블로그 연동 | 네이버 블로그 콘텐츠를 홈페이지에 노출 | 별도 설계 (후속) |
| 3. 채용공고 연동 | 채용 정보 실데이터 연동 | 별도 설계 (후속) |
| 4. (검토) 로그인/계정 기능 | 현재 Nav의 "로그인"이 실제로 무엇을 하는지는 미확인 | 이번 범위 밖, 그대로 유지만 |

**명시적으로 범위에서 제외:** Pilot 섹션의 "세무사 브랜드메시지 서비스"는 아직 검증되지 않은 신규 파일럿이므로 홈페이지에 노출하지 않는다. 경쟁사명(뉴닉 등)은 어떤 형태로도 절대 언급하지 않는다.

## 아키텍처

- **프레임워크:** Next.js (App Router, TypeScript) — 정적 마케팅 페이지지만, 향후 로그인/블로그/채용 같은 앱적 기능 확장을 고려해 선택. 배포는 Vercel.
- **스타일링:** Tailwind CSS + CSS 변수로 디자인 토큰 관리 (컬러, 그라디언트, 간격). 기존 index.html의 CSS 변수 체계(`--orange #FF6B35`, `--yellow #FFB800`, `--peach #FFF3EC` 등)를 토큰으로 그대로 승계한다.
- **폰트:** 기존과 동일하게 Google Fonts의 `Gmarket Sans`(제목) + `Noto Sans KR`(본문), `next/font/google`로 로드해 self-host 처리(현재는 외부 CDN 직접 로드 방식).
- **도메인:** 가비아(Gabia)에서 관리 중인 `nugget.im`의 A/CNAME 레코드를 Vercel이 안내하는 값으로 교체. 네임서버는 가비아 그대로 유지.
- **콘텐츠:** 이 단계에서는 블로그·채용 데이터 연동이 없으므로 전 섹션이 정적 컴포넌트다. 외부 데이터 소스는 아직 붙이지 않는다.

## 컴포넌트 구성

`app/page.tsx`가 아래 섹션 컴포넌트를 조립한다. 기존 사이트의 섹션을 기반으로, 신규/변경 사항을 표시했다.

| 컴포넌트 | 상태 | 내용 |
|---|---|---|
| `Nav` | 유지 | 로고, 메뉴, 검색, 로그인 — 로고는 신규 추출한 벡터 자산(`assets/nugget-logo-*.svg`) 사용 |
| `Hero` | **재설계** | Warm Editorial 톤: 화이트~피치 그라디언트 배경, 압도적 크기의 볼드 타이포, 오렌지 포인트 컬러. 정적 이미지/영상 대신 **미세한 그라디언트 모션**(CSS `background-position` 애니메이션)만 적용 — 실사 영상 자산이 없기 때문 |
| `Ticker` | 유지 | 기존 자동 스크롤 배너 |
| `StatsBand` | 유지 | 기존 4개 통계 다크 밴드 |
| `CaseStudy` | **신규 (기존 case-card 확장)** | 매체소개서의 "고객사 A" 사례(MAU 10만→50만, 콘텐츠 뷰 3만+ 증가)를 다크 배경 + before/after 막대그래프로 시각화. 경쟁사·타사 비교 문구는 절대 사용하지 않고 절대 수치만 사용 |
| `Clients` | 유지 | 기존에 이미 공개 노출 중인 로고(KB국민은행·카카오·네이버 등)만 유지. 세일즈 CRM에 있는 미계약/협상중 리드는 어떤 경우에도 노출하지 않는다 |
| `ContentLineup` | 유지 (카피만 보강) | 기존 7개 카테고리 탭 구조 유지, 매체소개서의 콘텐츠 분류(데일리 경제뉴스/재테크 상식/한입 뉴스)를 반영해 설명 카피 보강 |
| `B2BServices` | **신규** | 매체소개서의 상품 카탈로그(콘텐츠 제휴: 데일리뉴스/재테크상식/한입뉴스/오리지널 제작/운영대행/사내교육용, 광고 상품: 한입뉴스형/기본형/이벤트결합형)를 카드로 노출. **가격은 공개하지 않고** 상품 카테고리와 "이런 기업에 추천합니다"류의 실제 세일즈 카피만 노출, CTA는 "가격 문의하기" |
| `Testimonials` | **신규** | 구독자 피드백 기반 인용. 이 설계 문서는 구조만 정의하며, 실제 인용 문구 선정은 구현 단계의 콘텐츠 작업으로 별도 진행 |
| `Subscribe` | 유지 | Stibee 외부 링크(`page.stibee.com/subscriptions/132031`) 그대로 유지 — 폼 자체가 없으므로 변경 불필요 |
| `Careers` | 유지 (실데이터 연동은 3단계) | 현재와 동일하게 정적 채용공고 1건 유지 |
| `Contact` | **버그 수정** | 현재 실제 전송 코드가 없어 입력 내용이 유실되는 상태. Next.js API Route(`/api/contact`)에서 이메일 발송 서비스로 `contact@nugget.im`에 실제 전달되도록 수정 |
| `Footer` | 유지 | |

## 시각 디자인 방향

브라우저 목업으로 검증한 최종 방향: **Warm Editorial 베이스 + 다크 대비 섹션**.

- **베이스(Hero, ContentLineup, Clients, Subscribe 등):** 기존 화이트~피치(`#FFF3EC`) 톤 유지, 타이포는 기존보다 더 크고 굵게(볼드 스테이트먼트)
- **대비 섹션(StatsBand, CaseStudy):** 다크(`#0a0a0a`~`#111`) 배경 + 오렌지/옐로 그라디언트 글로우 포인트 — 기존 StatsBand의 다크 톤 패턴을 CaseStudy로 확장하는 것이라 기존 시각 언어와 충돌 없음
- **로고:** `.ai` 원본에서 추출한 벡터 사용 — 라이트 배경엔 컬러 그라디언트 버전, 다크 배경 위에서도 컬러 버전이 충분히 선명해 기본으로 사용하고, 화이트 모노톤 버전은 사진/복잡한 배경 위 등 예외 상황에 예비로 둔다
- **마스코트(냠냐미):** 이번 개편에는 포함하지 않는다
- **모션:** 영상 자산이 없으므로 히어로는 저채도 그라디언트가 서서히 움직이는 CSS 애니메이션만 사용. 무거운 3D/파티클 등은 이번 범위에 넣지 않는다

## 데이터 흐름

이 단계는 정적 콘텐츠 위주라 데이터 흐름이 단순하다.

1. **구독:** 사용자가 "무료 구독하기" 클릭 → Stibee 외부 페이지로 새 탭 이동 (기존과 동일, 변경 없음)
2. **문의:** 사용자가 문의폼 제출 → `/api/contact` (Next.js Route Handler) → 이메일 발송 서비스(예: Resend) → `contact@nugget.im` 수신. 제출 즉시 프론트엔드에 성공/실패 상태를 반영 (현재처럼 무조건 성공 UI만 보여주지 않는다)

## 에러 처리

- 문의폼: 필수 항목 누락/이메일 형식 오류는 클라이언트 검증(기존 로직 유지), 서버 전송 실패 시 사용자에게 명확한 실패 메시지와 재시도 안내를 보여준다 (현재는 실패해도 무조건 성공 화면이 뜨는 상태 — 이 부분이 가장 중요한 수정 포인트)
- 이미지/폰트 로드 실패에 대비한 fallback (시스템 폰트 스택, alt 텍스트)
- 404 페이지 기본 제공(Next.js 기본)

## 테스트

- TypeScript 타입 체크, ESLint
- 반응형 브레이크포인트 수동 확인: 기존과 동일한 기준(Tablet ≤960px, Mobile ≤600px)
- **문의폼은 배포 전 실제로 `contact@nugget.im`에 이메일이 도착하는지 수동으로 반드시 확인** (지금까지 아무도 몰랐던 버그였으므로)
- 기존 imweb 사이트와 새 사이트를 나란히 놓고 섹션별 시각 회귀 확인(수동)

## 이번 문서에서 확정하지 않고 넘어가는 것

- **B2B 상품 가격 공개 여부:** 이 설계에서는 "비공개, 카테고리만 노출"로 기본값을 잡았다. 다른 의견이 있으면 리뷰 시 알려달라.
- **테스티모니얼 실제 문구:** 어떤 피드백을 인용할지는 콘텐츠 작업이며 구현 단계에서 별도로 진행한다.
- **이메일 발송 서비스 선택:** Resend를 기본으로 제안했으나 계정/비용 관련 확정은 구현 단계에서 논의한다.
